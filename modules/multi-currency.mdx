The Multi-currency [Module](/concepts/modules) lets a [Store](/resources/glossary#store) sell in more than one currency. Catalog prices stay in the store's primary currency; the Module computes display prices in the [Shopper](/resources/glossary#shopper)'s chosen currency from current exchange rates. When the payment provider supports it, the charge itself uses that currency. You can also set a per-product override for any price you do not want derived from an exchange rate.

**Source:** [`modules/multi-currency`](https://github.com/86d-app/86d/tree/main/modules/multi-currency) · **npm:** [`@86d-app/multi-currency`](https://www.npmjs.com/package/@86d-app/multi-currency)

## Installation

```sh
86d module add multi-currency
```

## Configuration

```ts
multiCurrency({
  primary: "USD",
  enabled: "USD,EUR,GBP,JPY",
  ratesProvider: "exchangerate-host",  // or "openexchangerates"
  refreshHours: "24",
});
```

## Components

- `<CurrencyPicker />`: [Storefront](/concepts/storefront) currency selector.

## Admin endpoints

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/admin/multi-currency/rates` | Current rates |
| `POST` | `/admin/multi-currency/refresh` | Force refresh |
| `POST` | `/admin/multi-currency/overrides` | Per-product price overrides |
