The Gift Cards [Module](/concepts/modules) preserves read access to existing digital gift card records. Each legacy card carries a unique code and recorded balance, and the Module projects its stored transaction history.

Issuance, purchase, top-up, credit, redemption, status mutation, and deletion are unavailable through Store, admin, and controller surfaces. These operations remain blocked until complete [Workflows](/concepts/agentic-design) can execute them with durable evidence, idempotency, and closed repair behavior. Existing balances, status, ownership, transaction history, and analytics remain readable.

A past expiration date appears consistently as `expired` in balance checks, lists, filters, and analytics without rewriting the stored legacy record. If a selected stored card or transaction cannot be validated, the affected endpoint returns an unavailable response instead of omitting the record or reporting partial balances, history, or totals.

**Source:** [`modules/giftcards`](https://github.com/86d-app/86d/tree/main/modules/giftcards) · **npm:** [`@86d-app/giftcards`](https://www.npmjs.com/package/@86d-app/giftcards)

## Installation

```sh
86d module add giftcards
```

## Store endpoints

| Method | Path | Authentication | Description |
| --- | --- | --- | --- |
| `GET` | `/gift-cards/check?code=...` | No | Check balance and status by code |
| `POST` | `/gift-cards/send` | Yes | Record intended email-delivery metadata for an owned gift card; this does not deliver a message |
| `GET` | `/gift-cards/my-cards` | Yes | List the signed-in [Customer's](/resources/glossary#customer) gift cards |

## Admin endpoints

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/admin/gift-cards` | List gift cards |
| `GET` | `/admin/gift-cards/stats` | Read gift card totals and balances |
| `GET` | `/admin/gift-cards/:id` | Read one gift card |
| `GET` | `/admin/gift-cards/:id/transactions` | List one gift card's transactions |
