86d is a commerce product you own. The [Store Runtime](/concepts/architecture) is MIT-licensed and runs on your infrastructure with your database, so the code and the commerce data stay yours. [86d.app](/introduction) is the optional managed product that provisions and operates that same runtime for you when you would rather not.

Creating a Store is the first hour. Operating one is every hour after, and that is the part 86d is built for: repricing, restocking, running a promotion, issuing a refund, reconciling a discrepancy. You can do that work yourself in [Store Admin](/concepts/admin), or delegate it to an agent that has to show you a [Change Set](/concepts/agentic-design) before anything lands.

These pages are written for two readers. If you run a Store, start with what a capability does and what you have to decide. If you are an agent acting on a Store, the exact contract is under each of those sections: options, endpoints, request and response shapes, and what happens when something fails.

## How a Store fits together

A Store Runtime is a Bun and Next.js monorepo built from composable [Modules](/concepts/modules). A Module can add API endpoints, [Store Admin](/concepts/admin) pages, and [Storefront](/concepts/storefront) components. You enable the ones you want in your active [Template](/concepts/templates), regenerate, and use the components in MDX.

<Steps>
  <Step title="Install and initialize">
    Install the `86d` CLI, then run `86d init`. It writes your environment file, installs dependencies, runs migrations, and seeds demo data with Store Admin credentials.
  </Step>
  <Step title="Choose your Modules">
    Edit the `modules` array in your active Template's `config.json`. First-party Modules live in the same repository you cloned. Treat external code as an advanced opt-in and read it before you install it.
  </Step>
  <Step title="Regenerate">
    `86d generate` rewrites the Module imports and the API router. Every enabled Module's components become available in MDX with no import statement.
  </Step>
  <Step title="Customize and deploy">
    Edit the Template's MDX to control layout and content, then push to Railway, Vercel, or any Docker host.
  </Step>
</Steps>
